Human-in-the-loop learning for robots in manufacturing

Ask, Assist, Learn

Robots, whether arms or humanoids, won't be 100% reliable on day one in a factory. This thesis builds the loop that gets them there: the robot works through a real shop-floor procedure, asks a remote operator for help only when it is unsure, and learns from every takeover, so one person can supervise more robots each week.

The problem

Reliability is the bottleneck, not the demo

A robot that succeeds 80% of the time at one task makes a good video and a bad employee. On a production line, the rare failures (a buried part, a misaligned fixture, a jammed clamp) stop the cell. Today the fix is a human, either standing next to the robot or teleoperating it full time. Neither scales.

Industry has already settled on the shape of the answer: robots run autonomously, a remote human handles the exceptions, and the exceptions become training data. The open questions are research questions: when the robot should ask, how a person takes over without friction, and how much each correction should improve the policy.

The idea

One loop: run, ask, assist, learn

  1. Run the SOP

    The robot executes a multi-step shop-floor procedure on its own.

  2. Know when to ask

    Low confidence, novelty or a predicted failure triggers a help request before damage happens.

  3. Operator takes over

    A remote operator jumps into that robot in VR, fixes the step, hands control back.

  4. Log the correction

    The takeover is saved with the state that caused it: a labeled example of the hard case.

  5. Retrain

    Interactive imitation learning plus RL fine-tuning focused on where the robot failed.
  6. ↺ Fewer help requests next round, so each operator can cover more robots.
System design

Three layers of autonomy, one human layer

Long-horizon tasks become tractable when a planner breaks the procedure into steps, so each learned skill only has to be reliable at one step. The same stack runs on a robot arm or a humanoid; only System 0 changes.

System 2SOP planner
Turns a procedure (or a work ticket) into an ordered list of steps and checks each one off.
Builds on Sequent: ticket to SOP to skill chain on a simulated Unitree G1.
System 1Skill policy
A learned policy (VLA or diffusion policy) executes each step and reports how confident it is.
Builds on Isaac Lab RL and sim-to-real work on the SO-101.
System 0Controller
Arm or whole-body control turns the policy's targets into safe joint commands.
Arm controllers for SO-101 and cobots; the lab's whole-body controllers for R1 / G1.
Human layerSupervisor + takeover
AR overview of every robot's step and confidence. When one asks, the operator takes over in VR, with haptic cues for contact.
Builds on Quest VR teleop and the Geomagic Touch force-feedback project.
Benchmark task

Machine tending: a real SOP with real failure modes

Loading and unloading a CNC or press is one of the most common manual jobs on a shop floor. It is long-horizon, every step can fail differently, and the steps repeat hundreds of times a shift, which is exactly the data a learning loop needs. Factories already tend machines with cobot arms, so results carry over whether or not humanoids take off.

Research questions

Three questions the thesis answers

RQ1 · Ask

When should a robot ask for help?

Compare confidence thresholds, novelty detection and learned failure predictors under a fixed budget of operator time.

RQ2 · Assist

How should the operator take over?

Design the handover: context shown before takeover, VR control, and whether force or haptic cues give better corrections.

RQ3 · Learn

How much does each correction buy?

Interactive imitation (HG-DAgger style) versus RL fine-tuning seeded by corrections, measured per minute of human time.

Why now

Research and industry are converging on this loop

The pieces exist separately. What is missing is the full loop on a long-horizon industrial task, on both robot arms and humanoids, measured in operator time.
