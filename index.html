Human-in-the-loop learning for robots in manufacturing

Ask, Assist, Learn

Factory robots, whether arms or humanoids, are rarely fully reliable when first deployed. This project studies a human-in-the-loop approach: the robot follows a standard operating procedure (SOP), asks a remote operator for help when its confidence is low, and learns from each correction, so that one operator can supervise more robots over time.

    Motivation

    Reliability limits deployment

    Learned manipulation policies now complete many factory tasks, but not every time. In production, an occasional failure such as a buried part, a misaligned fixture or a clamp collision still stops the cell. Today that gap is covered by a person on site or a full-time teleoperator, which does not scale.

    A common pattern in industry is to let robots run on their own, route the exceptions to a remote operator, and use those exceptions as training data. This project studies three parts of that pattern: when the robot should ask, how the operator takes over, and how much each correction improves the policy.

    Approach

    Run, ask, assist, learn

    Test task: machine tending, a six-step SOP (pick, load, start, wait, unload, place) that cobot arms already do in many plants and humanoids are starting to.

    1. Run the SOP

      The robot executes a multi-step procedure on its own.

    2. Ask for help

      Low confidence or a predicted failure triggers a request before contact.

    3. Operator assists

      A remote operator takes over in VR, completes the step and hands back control.

    4. Log the correction

      The takeover is stored with the state that caused it.

    5. Retrain

      The policy is updated on the new data, with extra weight on the failure cases.
    6. ↺ Fewer requests each round, so one operator can cover more robots.
    System design

    Three autonomy layers and a human layer

    A planner splits the procedure into steps, so each learned skill only has to be reliable on one step. The same stack applies to a robot arm and a humanoid; only System 0 changes.

    System 2SOP planner
    Converts a procedure or work ticket into ordered steps and tracks progress. The step logic (order, safety rules, when to stop and ask) can be synthesized from temporal logic specifications, so it is guaranteed correct; learning stays inside each step.
    Builds on Sequent: ticket to SOP to skill chain on a simulated Unitree G1, and the lab's reactive synthesis work (Schlossman et al., IROS 2019).
    System 1Skill policy
    A learned policy executes each step and reports a confidence score.
    Builds on Isaac Lab RL and sim-to-real work on the SO-101.
    System 0Controller
    Arm or whole-body control converts policy targets into joint commands.
    Arm controllers for SO-101 and cobots; the lab's whole-body controllers for R1 / G1.
    Human layerSupervisor + takeover
    An AR overview of each robot's step and confidence. On request, the operator takes over in VR, with optional haptic feedback.
    Builds on Quest VR teleop and the Geomagic Touch force-feedback project.
    Learning setup

    Models and training

    What is learned: the manipulation skills for each SOP step (pick, load, unload, place), and a model of when those skills are about to fail. The research question is how to make them reliable with the least operator time.

    Each skill is trained in three stages: imitation on demonstrations, imitation on operator corrections, then RL fine-tuning in simulation for the precise steps. The loop works with any imitation-trained policy, including a fine-tuned vision-language-action (VLA) model.

    Research questions

    Three questions

    RQ1 · Ask

    When should a robot ask for help?

    Compare confidence thresholds, novelty detection and learned failure predictors under a fixed operator-time budget.

    RQ2 · Assist

    How should the operator take over?

    Compare handover designs: context shown before takeover, VR control, and whether haptic cues improve corrections.

    RQ3 · Learn

    How much does each correction help?

    Compare interactive imitation with RL fine-tuning from corrections, measured per minute of operator time.

    Prior work

    Related work

    Learning from human corrections now works on industrial tasks (PACER, GR-BC at CoRL 2026). The open gap: deciding when to ask using the SOP step and its risk, measuring cost in operator time, and one operator supervising several robots.

    WorkVenueWhat it shows
    HG-DAggerICRA 2019 · StanfordA human expert takes over only when needed; learning from those takeovers beat DAgger and behavior cloning in real driving tests.
    Human-aware controller synthesisHCRLIROS 2019 · UT AustinA mobile manipulator's controller is synthesized from temporal logic so it is guaranteed to keep a human workstation supplied without overloading the worker. The model for a guaranteed operator-workload limit.
    ThriftyDAggerCoRL 2021 · BerkeleyThe robot decides when to ask, requesting help only in novel or risky states, within a fixed human budget.
    Fleet-DAggerCoRL 2022 · BerkeleyMany robots, few humans. Smart allocation gave up to 8.8x higher return on human effort in a 100-robot simulation.
    SiriusRSS 2023 · UT AustinRobots learn on the job from human interventions during deployment; 27% better than prior methods on real hardware.
    Sirius-FleetCoRL 2024 · UT AustinLearned failure predictors decide when a fleet needs a human, and human workload falls as the robots improve.
    HIL-SERL2024 · BerkeleyDemos plus human corrections plus RL reach near-perfect success on precise assembly after 1 to 2.5 hours of real training.
    π*0.6 with Recap2025 · Physical IntelligenceTeleoperator corrections plus the robot's own experience more than doubled throughput on the hardest tasks; the robot assembled boxes in a real factory.
    PACERCoRL 2026A VLA learns from human corrections in multi-step robotic disassembly: 87/100 trials vs. 54/100 for standard fine-tuning. Closest prior work.
    GR-BCCoRL 2026Reweighting human interventions by progress took graphics-card assembly from 0% to 92% in three rounds, vs. 63% for DAgger-style data mixing.
    Learning While DeployingCoRL 2026Fleet RL on autonomous rollouts plus human interventions across 16 robots; 95% average success, with the largest gains on long tasks.
    ContactGuardCoRL 2026Predicts grasp failure before contact for ACT policies (ROC AUC 0.90 to 0.99), supporting help requests before contact.
